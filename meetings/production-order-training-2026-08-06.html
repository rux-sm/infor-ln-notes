Session Summary

Production Order Training

A first walk through creating, releasing and closing a production order — including one segment that demonstrates the screens but is explicitly not a clean procedure to copy.

Session Date2026-08-06
TypeTraining Session
Orientation only. This is the shareable half of a longer internal record. It carries no citations, and nothing here should be relied on for implementation work without checking it against official Infor documentation.

What this covered

A walkthrough of a full job-shop production order: setting up the item data, building an order, releasing it, issuing material, reporting it complete, and closing it.

Topics

The production data chain

The demo built or reviewed a manufactured item, a component item, a job-shop bill of material, a job-shop routing, and costing data, then created a production order from them. This is the dependency order that matters: item, then BOM and routing, then costing, then the order itself — each step needs the one before it to exist first.

What was shown, in order:

  1. Item tcibd0501m100 — manufactured item ITEM-A with component ITEM-A.1.
  2. Job Shop BOM tibom3100m000 — bill of material JB0000236, status Approved, with Approve Revision and Use for Planning actions available on the record. Only one BOM per item and site can actually be used for planning at a time (same rule for costing) — that's what "Use for Planning" / "Use for Costing" mean: which one wins, not just a label.
  3. Job Shop Routing tirou4600m000 — routing 0, operation 10, work center ASM-01, a 60-minute cycle time. That cycle time is defined against a specific batch size (the routing's own "quantity" setting) — it isn't automatically "60 minutes per single unit" unless that batch size is 1.
  4. Item - Costing ticpr0107m000 — costing data for the item.
  5. Production Order tisfc0101m100 — the order itself, built from the item/BOM/routing/costing above.

Order statuses, start to finish

Across the session the order moved through a clear sequence of states: Created, then Released, then Active, then Completed. Recognizing these five words on a production order tells you where it is in its life without needing to know every step that produced them.

Two of these are precise, not just labels: Released happens specifically when someone releases the order to the job shop — that's literally what the Release action does. Active happens the moment any real transaction occurs against the order, such as issuing material — it isn't triggered by Release alone.

Reporting progress and closing the order

Once the order was released and active, the operation was reported complete and the order walked through to closing:

  1. (56:20) In Report Operations Completed tisfc0130m000, entered 1 as Additional Completed.
  2. (57:20) Report Orders Completed tisfc0120s000 showed Quantity Delivered 1 — this is the finished-goods quantity that gets posted into inventory. After saving, Production Orders tisfc0501m000 showed the order as Completed.
  3. Close Production Orders opened next, as the final step once nothing is left open on the order.

The material-issue segment had a mistake — don't copy it

(54:48–55:28) In Material to Issue for Production Orders ticst0101m100, the Initiate action was used and the warehouse quantity changed to 1 — but the wrong warehouse/shop-floor path was picked along the way, and noted at the time. That segment proves the screen and the action exist, but it is not a clean procedure to follow step-by-step. A corrected, clean run of the same process was completed later, in the 2026-08-11 session.

What Initiate actually does: it unblocks the material's warehouse order line so the warehouse can start moving that material toward the job shop. Depending on two settings, this can happen automatically the moment the order is released, or it can require running this action by hand — which setting applies here wasn't confirmed.

What was decided

Nothing was formally decided — this was a training demonstration, not a planning meeting. The useful output is the flow itself and a list of things worth double-checking before treating any of it as a fixed procedure.

Key takeaways

  • The core chain to learn is: item → BOM → routing → costing → order → release → material issue → report complete → close.
  • The five statuses to recognize on a production order are Created, Released, Active, Completed (and later, closed) — Released comes from the Release action specifically, Active from the first real transaction (like a material issue).
  • Only one BOM (and one routing) per item/site can actually be "used for planning" or "used for costing" at a time — the check box picks the winner.
  • A cycle time is tied to a batch size, not automatically "per unit" — check the routing's basis quantity before doing simple multiplication.
  • Don't reuse the material-issue steps from this session directly (54:48–55:28) — that segment had a known warehouse-selection mistake.
  • A later session (2026-08-11) redid material issue cleanly, start to finish.
