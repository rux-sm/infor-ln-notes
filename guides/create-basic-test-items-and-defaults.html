Create Basic Test Items and Defaults

create a small, isolated item family that proves two supply patterns — purchased components and a Job Shop finished product — and carry it through the engineering, costing, and stock data a quantity-one production order needs, so the finished item can be produced and received into the finished-goods warehouse.

Official help separates two concepts, and tcibd0502m000's own help now states both in its own words:

- An active subentity indicator — the help calls it Ordering Data, Purchase Data, Warehousing Data, and so on — means "you have specified default item data in the {defaults} session". The button beside it starts that defaults session. - A selected Create Item - {subentity} control means that "based on the item {subentity} defaults, {subentity} data is created for new items" in a named target session: Item - Ordering tcibd2600m000, Item - Purchase tdipu0601m000, Item - Warehousing whwmd4600m000, Item - Production tiipd0601m000, and Item - Sales tdisa0601m000.

The Sites check box on this session decides whether phase 5 and 6 get a site row for free. When it is selected, "local item data is automatically generated for the linked sites when you specify a new item" in Item tcibd0501m100. When it is cleared, the site data must be generated by hand — with the Create Items by Site command on the appropriate menu of the Sites tab. That is the setting behind the empty Sites grid the 2026-08-16 run hit.

The site-row warehouse is ADNA02 in the observed multisite flow. Item Ordering Defaults itself did not display a Warehouse field on any of its three tabs.

This session is not opened from the menu: its help states it "is started when you specify or modify global item defaults in the Item Defaults tcibd0102m000 session" — which is why step 2.11 continues in it rather than navigating to it.

Official help states that a green package-default indicator does not create the site subentity by itself. The corresponding Create Item control must be selected.

When Centrally Managed is selected, the site Create controls take the values from Item Defaults tcibd0502m000 and are disabled here. When it is cleared, site-specific Create controls can be maintained here. If no local package default exists, LN can use the global package default for the site.

What "no local default" means is now sourced. Item Defaults by Site tcibd1551m000 holds the site-level defaults for a site, item type, and item group; its help states that "if item defaults for a site are not specified in this session, the global item data is used for defaulting", and that the global item data is also used when the Use Global Item check box is selected in Items by Site tcibd1550m000. So for this test family, leaving the site defaults empty is a valid outcome, not a missing step — the global combination built in phases 2 and 3 is what applies. Item - Production Defaults by Site tiipd0152m000 is the made-group equivalent for production data.

Missing the current Sites activation and Centrally Managed values for the new groups are still not captured, OI-073 and OI-095.

Missing the purchased-side site session, Item Purchase Defaults by Site tdipu0182m000, has no filed help, OI-095.

Approval is not cosmetic. Official help states that only job shop bills of material with status Approved can be used for manufacture. A BOM left at New will not carry the pair into a production order.

The two indicators are separate from approval and from each other:

- Use for Planning — per item and site, only one job shop BOM can hold it. - Use for Costing — only one job shop BOM per product can hold it.

Both are Actions-menu commands run against a selected row, not fields typed into the header. The help lists them as Approve Revision, Expire Revision, Use for Planning Indicator, and Use for Costing Indicator; the 2026-08-06 frame shows the first and third promoted onto the toolbar as APPROVE REVISION and USE FOR PLANNING, beside the Actions menu. That frame also shows a row at status Approved with both indicators still cleared — approval and the two indicators genuinely are three separate actions, and doing one does not do the others.

Why the effective date matters. The production order's Reference Date "determines the selection of operation lines and BOM lines", and the order's BOM revision defaults to "the revision valid on the reference date". A BOM made effective after the order's reference date is not selected, and the order arrives with no materials.

Leaving Routing blank on the BOM header is deliberate: "A bill of material may be linked to a specific routing. If this field is empty, the bill of material can be used with any routing." Linking it here would couple this BOM to the routing built in phase 9 before that routing has been proven.

Do not add a semi-finished level. The single-level structure from the phase 6 notes is the whole design: pair ← 2 rods + 1 sleeve.

The material line is where the issuing warehouse is set. tibom3110m000 carries Position (the JSBOM line number), Item (the material), Warehouse, Net Quantity, Scrap Percentage, Scrap Quantity, and Operation (the operation where the material is used). Net Quantity is the quantity field — not "quantity" — and Net Quantity in BOM Unit beside it applies only when BOM units are switched on in Product Engineering Parameters timfc0100m000 and Use BOM Units is selected on the BOM header. This test uses the item unit, so leave BOM units alone.

Operation on the material line links a material to the operation that consumes it. With one operation this is optional detail; with several it decides when each material is needed.

The Job Shop by Site setting lives in two places, not three. tibom3110m000's help names both in one breath: the Job Shop by Site parameter in Concept Activation tcemm4600m000 must be Active or In Preparation, *and* the Job Shop by Site check box in Implemented Software Components must be selected. The now-filed tccom0500m000 export confirms it holds a Job Shop by Site field describing "the activation status of the use of site specific job shop production bills of materials and routings". Other help files call that session tccom0100s000. Missing whether this deployment exposes tccom0500m000, tccom0100s000, or both is still uncaptured, OI-098.

Routing Quantity is "the quantity of product on which the cycle time is based". Setting it to 1 is what makes step 9.14's cycle time the time for one pair. This is the point the 2026-08-06 narration got loose about — a 60-minute cycle time only means "60 minutes per unit" when the routing quantity is 1.

Use for Planning behaves differently here than on the BOM. More than one routing may hold it for an item, provided their quantity ranges do not overlap. Use for Costing is still one at a time: "Only one job shop routing is used for costing purposes."

Why a master-data guide checks costing at all. Calculate Estimated End Item Unit Costs ticst0210m000 reads material standard costs to total an order's material cost. Its Check Existence of Material Standard Costs option decides what happens when one is absent: selected, "LN generates an error report and terminates the calculation"; cleared, the estimate is simply too low. Purchased items get their standard cost from purchase data. Official help states that for a purchased item, the standard cost in this session "is calculated based on the Purchase Price Priority levels in the Cost Calculation Codes ticpr1100m000 session". BAM-ROD and BAM-SLEEVE therefore will not acquire a standard cost until purchase price data exists for them — which is an argument for phase 11's route A.

Item - Costing does not create items. Its own help says so: when the session is reached by zooming you can only find and select a record; new items are created in Items tcibd0501m000. If a costing record is missing, that is a costing setup task, not an item task.

Where the numbers come from. Item Standard Costs ticpr3501m000 displays "actual and/or historical standard cost structures by item and date combination" — it is the read-only history behind the single figure ticpr0107m000 shows, and the place to look when a cost is present but not the one you expected. Standard Cost Calculation Parameters ticpr0100m000 holds the module's parameters, including Standard Cost per EU Mandatory, which decides whether a per-enterprise-unit cost is required at all.

Whether Enterprise Unit appears on these screens depends on Standard Cost by Enterprise Unit being Active in Implemented Software Components tccom0100s000.

All four sit under Common ➔ Standard Costs — Item - Costing and Cost Calculation Codes under ➔ Master Data, Item Standard Costs under ➔ Item Costs, and Parameters directly beneath (../03_supplementary/EX/EX_navigation-tree_2026-08-20.txt, 2026-08-20).
