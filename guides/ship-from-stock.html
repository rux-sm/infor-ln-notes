Stock is usually spread across several warehouses. Pick the one you will ship from and record it — phase 1 step 1.6 needs it, and an order raised against a warehouse that does not hold the stock will not advise.

On-hand is not what you can sell. Allocated may already commit most of it.

The _Lines ready for_ panel does not act. It counts lines. Clicking RELEASE TO WAREHOUSING there only toggles a green tick — the release runs from Actions. Verified 2026-08-08, OI-026.

Two sessions sit behind this action. Release Sales Order Lines to Warehousing tdsls4501m140 is the entry point; Release Sales Orders to Warehousing tdsls4246m000 opens from its appropriate menu. Individual lines can also be released directly.

Activities 1 is the diagnostic. If an activity reads Automatic: No, it never fires on approval in this configuration and must be run by hand.

Upto Release Date is a cutoff, not a calendar guard. The session processes only sales order lines whose Release Date (defaults to planned delivery date minus the outbound lead time) is on or before the entered date. Source: tdsls4246m000_Release_Sales_Orders_to_Warehousing_2026-08-11.pdf, Field Information ➔ Upto Release Date. Closes OI-028.

This phase is optional in LN, and mandatory here. Two conditions, both met in this environment:

1. The _Picking List_ activity is set to Automatic = No in this environment's outbound procedure — verified 2026-08-09, ../03_supplementary/LC/LC_Warehousing_Parameters.md section 4. Where it is not an activity at all, LN ticks Picked on release and the phase vanishes. 2. The picking list activity is only available for location-controlled warehouses.

Note that _Generate Picking List_ is automatic and _Picking List_ is not. The list appears without being asked for; confirming it is yours to do, and only confirming moves the quantity into Picked.

Change either and phase 4 disappears. So "you must run the pick" is a statement about this configuration, not about LN.

With outbound inspection in the procedure, the line status becomes To be Inspected rather than Staged.

Staged is the normal shipment-creation boundary. LN generates a shipment line, tries to link it to an existing compatible shipment, and creates a new shipment if no match exists. Matching includes ship-from/to data, addresses, delivery terms, shipment procedure, route, carrier, and planned delivery date. The Shipment field on Shipment Lines is the shipment header number; the adjacent shipment-line value is only its position. Source: ln_2026.x_whoutbshipmug__Outbound_and_Shipments.pdf, Warehousing Loads and Shipments; whinh4131m000_Shipment_Lines_2026-08-09.pdf, Field Information.

Statuses: Projected · Open · Frozen · Confirmed. The status is always derived, never set directly. Projected applies only where Projected Shipments in use is configured, and never to manual shipments.

Freezing is mandatory in this environment. Freeze Mandatory is ticked on the shipment, carried from the linked line in Shipment Lines whinh4131m000 — verified 2026-08-09. Session help for that session traces it one level further: the check box is taken from the Freeze Mandatory check box on Warehousing Order Types whinh0110m000 — the shipment and its line only display it, the value is set there. That record itself has not been opened in this environment. It is conditional in the product; it is not conditional here, so 5.3 cannot be skipped.

Freeze and Confirm are both Actions entries and toolbar buttons, with shortcuts Shift+F and Shift+C. Confirm is greyed until the shipment is Frozen — that greying is the check that 5.3 worked. Re-open (Shift+O) reverses a freeze.

There is also a bulk route. Warehousing ➔ Shipments ➔ Freeze/Confirm Shipments/Loads is a session of its own, and it is the activity the outbound procedure actually names. Use it for several shipments at once.

The rest of the Actions menu, verified 2026-08-09 — Submit for Acceptance · Undo Submit for Acceptance · Compose Load… · Compose Shipment… · Compose Shipping Container… · Compose Shipping Structure · Publish Shipment · Freeze · Re-open · Confirm · Freeze/Confirm… · Cancel… · Confirm Outbound ASN… · Remove Confirmed Shipments… · Check Document Compliance · Handling Units ▸ · Print Certificate of Conformance · Print ▸ · Export and Import ▸

The shipment carries its own procedure — 20S, *SO/SC (Documents=Yes)* in the verified run. Separate from the warehousing order's order type.

_Shipped Quantity_ defaults to the Picked Quantity. Decreasing it raises Not Shipped Quantity on the shipment line and Expected Not Shipped Quantity on the outbound order line. The edit happens on Shipment Lines `whinh4131m000` — its own session help confirms this directly: "if the shipment line is not yet confirmed, you can manually decrease the Shipped Quantity," closing OI-060. Step 5.2 already pointed here; it was correct, just unconfirmed. Source: whinh4131m000_Shipment_Lines_2026-08-09.pdf, Field Information; whinh2120m000_Outbound_Order_Lines_2026-08-09.pdf, Field Information.

Confirming is a one-way door. Inventory is relieved; a correction from here needs a return shipment. Lines can no longer be added or removed unless Allow Changes to Shipment is set.
