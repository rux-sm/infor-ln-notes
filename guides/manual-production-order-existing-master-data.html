Scenario Guide

Manual Production Order from Existing Master Data

create a quantity-one manual production order from an existing finished item, existing components, an existing BOM, and an existing routing; verify the generated operations and estimated materials; release the order; issue material to the job shop; report the operation(s) complete; and confirm the finished item is received into the warehouse.

Prerequisite Use existing master data only. Do not create, approve, expire, or repair an item, BOM, routing, work center, warehouse relationship, or costing record while following this guide. Where a training case comes from. If none has been handed to you, SG-create-basic-test-items-and-defaults.md builds one: its phases 0–7 create the items, phases 8–11 add the BOM, routing, costing, and component stock, and its phase 12 hands over exactly the values step 0.5 above asks for.

The 2026-08-11 recording showed that a multilevel BOM loop can prevent a clean order-creation exercise. If validation reports a loop or the expected BOM/routing cannot be identified, stop and return the training case to the master-data owner. The supported correction route remains under OI-083.

Inventory on Hand is an observed quantity, not a promise that the quantity is available to issue. This phase uses it only as a basic preflight; allocation and availability meanings remain outside this guide.

Step 0.6 gives phase 5 the baseline it verifies against — this guide's endpoint is a confirmed on-hand increase at the receiving warehouse, not just a status change on the order.

The official Production Orders help defines Quantity Ordered as the quantity to be produced and Warehouse as the warehouse where the produced items are stored. It also states that forward planning derives delivery from production start, while backward planning derives production start from planned delivery.

The Reference Date determines which operation and BOM lines are selected. Do not experiment with dates or revisions in this basic run; use the qualified values supplied in phase 0.

The official help for Release Production Orders states plainly what this action does: "Use this session to release production orders to the job shop. The production order status changes to Released." A released order is one where "production can start, for example, materials can be issued, and spent hours can be accounted."

Releasing also creates the warehousing side of the order. The same help states that LN creates warehousing orders through which "the issue of materials and receipt into inventory of end products are handled" — one order to move the component out of the warehouse identified in step 0.4, one to receive the finished item into the warehouse from step 1.5. Phase 4 works the first; phase 5 depends on the second reaching its own completion.

This session's Selection Range fields are built for releasing many orders at once, by site, order, item group, work center, and other ranges — this guide narrows to the single order from phase 1 and does not exercise batch release. Check Shortages, quality-inspection order creation, and the shop-floor-warehouse allocation move this session can also perform are not exercised here; they depend on Production Order Parameters tisfc0100s000 settings this library cannot yet confirm.

Missing whether Release Production Orders tisfc0204m000 also has a standalone menu entry, separate from the Actions menu route used here, is unconfirmed — OI-018.

Material to Issue for Production Orders ticst0101m100 is where the estimated materials LN generated from the BOM and routing (already visible in phase 2) become quantities to move: "you can use this session to view and maintain material quantities which must be issued from the warehouse to the production center."

Two check boxes on this session's material line decide how much of steps 4.3–4.7 LN does for you:

- Direct Initiate Inventory Issue — if selected, the line unblocks automatically on release (step 3.4), and step 4.3 is not needed. - Direct Process Warehouse Order Line — if selected, the whole outbound procedure (steps 4.4–4.7) runs automatically once the line is unblocked. If cleared, Activities by Warehousing Order whinh2104m000 decides which outbound activities are automatic and which are manual.

Which of these two check boxes is set for Company 4100 is not confirmed — OI-083. Steps 4.3–4.7 are written for the case observed on 2026-08-11, where Generate and Release Outbound Advice were both run manually. If this environment has either box selected, some of those steps will already be done when you reach them; do not treat their absence as an error.

Actual Quantity is "updated by Warehousing," and each update also books a WIP financial transaction — this is the mechanism behind Production Orders' Active status: it triggers specifically because a WIP transaction, such as this material issue, has occurred against the order, not from release alone.

Report Operations Completed tisfc0130m000 reports progress "by reporting quantities as completed or rejected for successive operations" — and "if you report progress on the last operation of the production order, it is possible to book the completed product into inventory." The Completed field is where an operation takes an additional completed quantity; for a quantity-one order reported for the first time, the full production quantity goes here.

Report Orders Completed tisfc0120s000 is the session the 2026-08-06 recording showed opening after the last operation was reported, displaying Quantity Delivered before save. It is a context-dependent subsession — Go To Session on it fails with "This session can only be started via another session" (SS_tisfc0120s000_cannot-be-opened-directly_2026-08-13.png) — so it has no independently exportable session help and no confirmed field list beyond what the recording showed. Step 5.5 is written from that single dated observation, not from official help.

Production Orders' own help defines Quantity Delivered as "the quantity of finished goods posted to inventory" and Quantity to Deliver as the completed quantity still waiting for Warehousing's inbound procedure — "when Warehousing finishes the inbound procedure, LN moves the applicable quantity from Quantity to Deliver to Quantity Delivered and resets Quantity to Deliver to zero." That inbound procedure is the production receipt warehousing order phase 3 creates alongside the issue order — whinh2100m000 showed it as a planned production receipt on 2026-08-11 for order 010000744, whose exercise stopped short of completion. Whether this receipt order needs the same kind of manual advice or receipt handling that phase 4's issue order needed, or completes automatically when the last operation is reported, is not confirmed — the same class of gap as OI-092's transfer-order receiving side, but for production receipts. Step 5.7's independent Inventory 360 check exists specifically so this phase's outcome is verified in Warehousing, not assumed from the Manufacturing-side status alone.

This guide ends here. Close Production Orders ticst0201m000 — calculating actual end-item unit cost and posting financial results — is out of scope; do not run it from this guide.
