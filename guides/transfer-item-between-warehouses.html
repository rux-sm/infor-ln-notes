Scenario Guide · v1.2

Transfer Item Between Warehouses

move a quantity of one item from a source warehouse to a destination warehouse, both in the same logistic company, using a manually created warehousing order — and verify that on-hand at the source dropped and on-hand at the destination rose by the same quantity.

Completion BoundarySource warehouse on-hand down and destination warehouse on-hand up by the transferred quantity
Run This Guide

0 · Confirm stock, destination, and expected order type

Warehousing ➔ Inventory 360 — Inventory 360 (whwmd4300m000)

0.1Enter the item in **Filter Items**, run it, tick the row, and open **Warehouse Inventory** in the **Inventory** groupWarehouse - Item Inventory (whwmd2515m000) opens, item carried through — item, source warehouse, source on-hand before
0.2In the same grid, find the row for the intended destination warehousedestination warehouse, destination on-hand before
0.3Open **Warehousing ➔ Master Data ➔ Order Procedures ➔ Default Order Types by Origin** (`whinh0120m000`)The default-order-type table opens
0.4Find the row with transaction type **Transfer**, ship-from **Warehouse**, and ship-to **Warehouse**expected warehousing order type; Create Shipment. For different source and destination warehouses, official help states Create Shipment = Always

1 · Create the transfer order

Warehousing ➔ Orders ➔ Orders — Warehousing Orders (whinh2100m000)

1.1Open **Warehousing ➔ Orders ➔ Orders**Warehousing Orders (whinh2100m000) opens
1.2Click **New**A blank warehousing-order header opens
1.3Set _Order_ origin to **Transfer (Manual)**This is one of the ten manual order origins listed in the session help — section 3.1
1.4Set _Inventory Transaction Type_ to **Transfer**Only settable by hand because the order has no originating package — section 3.1
1.5Set _Ship-From Code_ to the source warehouse from 0.1, and _Ship-To Code_ to the destination warehouse from 0.2Both types read Warehouse — the condition for the Transfer transaction type
1.6Compare the defaulted _Warehousing Order Type_ with step 0.4 and record the value actually usedactual warehousing order type
1.7Save the headertransfer order number
1.8Add an order line: the item from 0.1 and the quantity to movetransferred quantity
1.9Save the line—

2 · Confirm the processing path and create advice

Warehousing ➔ Orders ➔ Outbound Line Status Overview — Outbound Line Status Overview (whinh2129m000); then return to Warehousing Order (whinh2100m100)

2.1Open **Outbound Line Status Overview** (`whinh2129m000`)The outbound-line overview opens
2.2Find the transfer order line from phase 1The item and order line match; Order Type matches the actual value from 1.6
2.3Read every row in the **Activities** table, especially _Finished_ and _Automatic_Automatic = Yes means LN runs it; Automatic = No means it is an operator step
2.4Record the activities marked **Automatic = No**manual outbound activities; these determine which later steps you perform
2.5If the first unfinished activity is automatic, return to the warehousing order and choose **Process**LN executes consecutive automatic activities and stops at the next manual activity
2.6If **Generate Outbound Advice** is manual, open **Outbound Lines**, select the line, and choose **Actions ➔ Advice ➔ Generate Advice**Advised fills; automatic follow-on activities may also finish
2.7If **Release Outbound Advice** is manual and _Released_ is still blank, choose **Actions ➔ Advice ➔ Release Advice**Released fills

3 · Pick the goods

Warehousing ➔ Outbound/Inspections ➔ Picking List — Picking List (whinh4525m100)

3.1Check the **Picking List** row recorded in phase 2If absent or already finished automatically, record Automatic / not applicable and skip 3.2–3.5; if Automatic = No, continue
3.2Find the Run for this orderThe line for your item and source warehouse
3.3Tick the line—
3.4**Actions ➔ Pick Run**Stock moves from the source location to staging. Picked fills on Outbound Lines
3.5Record the Run number from the headerpicking list Run number

4 · Ship

Warehousing ➔ Shipments ➔ Shipments — Shipments (whinh4130m000), then drill in to Shipment (whinh4630m000)

4.1Check the **Freeze/Confirm Shipments/Loads** row recorded in phase 2If already finished automatically, record Automatic / not observed and skip 4.2–4.4; if Automatic = No, continue
4.2Find the shipment for this order and drill inshipment number
4.3If _Freeze Mandatory_ is ticked, choose **Actions ➔ Freeze**Status = Frozen
4.4Choose **Actions ➔ Confirm**Status = Confirmed. Inventory leaves the source warehouse

5 · Receive at the destination

Warehousing Order (whinh2100m100) — the same order number from phase 1, Inbound Lines / Receipt Lines tab

5.1Open the **Inbound Lines** tab on the transfer orderThe inbound side of the same order, ship-to = destination warehouse
5.2Select the inbound line and choose **Actions ➔ Receipt**Warehouse Receipt (whinh3512m000) opens for the transfer line
5.3Select the receipt line and choose **Actions ➔ Confirm**The receipt is confirmed and the destination inventory is updated
