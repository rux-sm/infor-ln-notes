Transfer Item Between Warehouses

ModuleWarehousing
StatusDraft
Versionv1.5
Updated2026-08-20
Steps33
Run This Guide

move a quantity of one item from a source warehouse to a destination warehouse, both in the same logistic company, using a manually created warehousing order — and verify that on-hand at the source dropped and on-hand at the destination rose by the same quantity.

Completion boundary: Source warehouse on-hand down and destination warehouse on-hand up by the transferred quantity

Phase 0 — Confirm stock, destination, and expected order type

0.4Find the row with transaction type Transfer, ship-from Warehouse, and ship-to Warehouse✎ expected warehousing order type; ✎ Create Shipment. For different source and destination warehouses, official help states Create Shipment = Always

This phase reuses the mechanics of SG-ship-from-stock.md phase 0, verified 2026-08-08/09 for the same two sessions. Nothing about reading inventory changes with the transaction type — only what happens to the order does.

Record on-hand at both ends before doing anything else. Phase 6's check depends on both starting figures, not just the source's.

The item does not determine the activity sequence. The default order type is selected from the order origin and transaction/ship-from/ship-to combination. Its warehousing procedure supplies the activities. Phase 0 records the expected default; phases 1–2 verify what the actual order line received, including any order- or line-level override.

If no matching default row exists, record Not configured and continue. Default Order Types by Origin is optional; the actual order header and activity table remain decisive.

A warehouse-to-warehouse transfer creates a shipment. Default Order Types by Origin whinh0120m000 states that when the source and destination are different warehouses, Create Shipment is Always; it is Never only when the source and destination are the same warehouse. The open question is therefore whether confirmation is automatic, not whether a shipment exists.

If a shipment is created, Freeze/Confirm mechanics — Actions entries and toolbar buttons, Shift+F/Shift+C, Confirm greyed until Frozen — are verified for this session generally in SG-ship-from-stock.md phase 5, 2026-08-09. Not re-verified for a transfer's shipment.

The 2026-08-15 run recorded no shipment number and reported that LN skipped the visible shipping process. Because this was a different-warehouse transfer, a shipment should have existed; the missing activity capture prevents determining whether LN automatically froze/confirmed it. Phase 2 now captures that distinction under OI-065.
